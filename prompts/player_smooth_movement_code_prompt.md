# 주인공 부드러운 타일 이동 코드 적용 프롬프트

## 목표

현재 주인공의 즉시 타일 이동을 시각적으로 부드러운 타일 보간 이동으로 변경한다. 논리적인 충돌 및 맵 좌표는 정수 타일 단위를 유지하고, 렌더링 위치만 이전 칸과 목적지 사이에서 보간한다. 기존 NPC 이동, 캐릭터 배치, 충돌, 맵 전환, 애니메이션과 자체 테스트가 계속 정상 동작해야 한다.

리소스 이미지와 JSON은 수정하지 않는다. C++ 코드와 관련 테스트만 수정한다.

## 현재 코드 기준

- 게임 루프와 입력: `src/Game.cpp`
- 카메라: `src/Camera.*`
- 캐릭터 배치 및 이동: `src/service/CharacterService.*`
- 캐릭터 런타임 액터: `src/manager/CharacterManager.*`
- 캐릭터 애니메이션: `src/model/Character.*`
- 맵 및 뷰: `src/manager/MapManger.*`
- 게임 설정: `src/game_config.json`

현재 NPC에는 다음 기능이 이미 있다.

- `CharacterService::NpcMovementState`에 출발 및 도착 위치와 보행 시간이 저장된다.
- `CharacterService::slide()`가 이전 타일과 새 타일 사이의 실수 좌표를 계산한다.
- `Game::drawGame()`이 `slide()` 결과를 사용해 NPC를 보간 렌더링한다.
- NPC 이동 중 애니메이션 프레임은 이동 진행도와 연동된다.

현재 주인공은 `CharacterService::movePlayer()`에서 `CharacterManager::move()`로 논리 좌표가 즉시 변경되며 NPC용 slide 상태를 사용하지 않는다. 이 차이를 제거하고 플레이어와 NPC가 공통 보간 구조를 사용하게 한다.

## 핵심 설계 원칙

논리 좌표와 시각 좌표를 분리한다.

- 논리 좌표: 정수 타일 좌표. 충돌, 맵 전환, 저장과 목적지 예약에 사용한다.
- 시각 좌표: 실수 타일 좌표. 렌더링과 카메라 이동에 사용한다.
- 이동을 시작할 때 목적지의 충돌을 검사하고 논리 위치를 예약한다.
- 화면에서는 이동 시간 동안 출발 위치에서 목적지까지 선형 보간한다.
- 캐릭터 이동에는 매 타일마다 감속하는 ease-in-out을 사용하지 않는다. 일정한 이동감을 위해 선형 보간을 기본으로 한다.

## 범용 이동 상태

NPC 전용 보간 상태를 플레이어도 사용할 수 있는 범용 액터 이동 상태로 확장한다.

추천 필드:

```cpp
struct ActorMotionState
{
    Cell from;
    Cell to;
    float elapsed = 0.f;
    float duration = 0.f;
    std::string direction;
    bool active = false;
};
```

정확한 타입명과 보관 위치는 현재 프로젝트 스타일에 맞춰 조정해도 된다. 다만 다음 조건을 지킨다.

1. 플레이어와 NPC 모두 같은 위치 보간 함수를 사용한다.
2. 이동 상태는 `instanceId` 문자열이 아니라 `Actor::instance` 정수 ID를 기준으로 조회한다. 플레이어는 안정적인 instanceId가 없을 수 있다.
3. NPC의 경로 인덱스, 대기 시간과 같은 AI 상태는 기존 상태에 유지하되 위치 보간에 필요한 필드는 공통 구조로 분리하거나 공통 접근 함수를 제공한다.
4. 런타임 이동 상태를 리소스 JSON에 기록하지 않는다.

추천 조회 함수:

```cpp
bool slide(int actorInstance, float& x, float& y, float& progress) const;
bool moving(int actorInstance) const;
```

`slide()`는 이동 중이면 보간된 타일 좌표와 0~1 사이의 진행도를 반환한다. 이동 중이 아니면 false를 반환하고 호출자는 액터의 정수 좌표를 사용한다.

## 플레이어 이동 시작

`CharacterService::movePlayer()`는 다음 순서로 처리한다.

1. 입력 step이 0이거나 맵 로딩 중이면 무시한다.
2. 플레이어가 이미 보간 이동 중이면 즉시 새 좌표로 이동하지 않는다.
3. 이동 중 받은 마지막 유효 방향 입력을 한 개만 버퍼링한다.
4. 이동이 끝나면 버퍼링된 방향을 우선 사용해 다음 타일 이동을 시작한다.
5. 이동 시작 시 현재 논리 위치를 `from`, 목적지를 `to`로 기록한다.
6. 목적지에 대해 기존 맵 통행 가능 여부와 캐릭터 충돌 검사를 수행한다.
7. 이동 가능하면 목적지 타일을 즉시 논리적으로 예약하고 `CharacterManager::move()`로 논리 좌표를 변경한다.
8. `duration = 1.f / playerSpeed`로 설정하고 elapsed를 0으로 초기화한다.
9. 캐릭터 방향을 변경하고 `body.walk(direction)`을 호출한다.
10. 목적지가 막혔다면 위치는 변경하지 않고 해당 방향의 `idle` 상태로 전환한다.

논리 위치를 이동 시작 시 목적지로 변경하는 이유는 보간 중 다른 캐릭터가 동일 목적지를 차지하지 못하게 하기 위함이다. 렌더링에서는 반드시 motion의 from/to를 사용한다.

## 플레이어 이동 갱신

프레임마다 delta time으로 플레이어 이동 상태를 갱신한다.

```cpp
elapsed += deltaSeconds;
progress = std::clamp(elapsed / duration, 0.f, 1.f);
visual = from + (to - from) * progress;
```

요구사항:

1. deltaSeconds가 비정상적으로 커지는 경우 한 프레임에 지나친 이동 처리가 발생하지 않도록 합리적인 상한을 둔다. 예: 0.05초.
2. progress가 1에 도달하면 현재 이동을 완료한다.
3. 방향키가 계속 눌려 있거나 방향 입력이 버퍼링돼 있으면 같은 프레임 또는 다음 갱신에서 다음 이동을 시작한다.
4. 다음 이동이 없으면 현재 방향의 `idle` 상태로 전환한다.
5. 한 프레임에 여러 타일을 건너뛰지 않는다.
6. 이동 도중 반대 방향 입력이 들어와도 현재 타일 이동을 완료한 뒤 다음 타일부터 새 방향을 적용한다.
7. 막힌 방향 입력은 캐릭터 방향만 변경하고 idle 상태를 유지한다.

## Game 입력 및 업데이트 루프

현재 키 반복용 `sf::Clock repeat`만으로 좌표를 즉시 변경하는 방식에 플레이어 motion 상태를 연결한다.

추천 방향은 입력 상태와 이동 업데이트를 분리하는 것이다.

- 이벤트 처리에서는 현재 눌린 방향과 마지막 입력 방향을 기록한다.
- 실제 타일 이동 시작은 프레임 업데이트 단계에서 `CharacterService`가 결정한다.
- 키 자동 반복 이벤트에 의존하지 않는다.
- 여러 방향키가 눌렸을 때는 가장 최근에 누른 방향을 우선한다.

게임 루프에서 delta time은 한 번만 계산한다.

```cpp
const float deltaSeconds = std::min(animation.restart().asSeconds(), 0.05f);
service_.advancePlayer(deltaSeconds, desiredDirection);
service_.advanceNpcs(deltaSeconds);
characters_.advance(deltaSeconds);
```

정확한 함수 형태는 프로젝트 스타일에 맞게 조정할 수 있다. `Game`은 입력 방향과 delta time만 전달하고 충돌, 예약, 좌표 변경과 이동 완료 판단은 `CharacterService`가 담당한다.

맵 로딩 중에는 플레이어와 NPC motion을 갱신하지 않는다. 로딩 분기에서 시계를 재시작하는 현재 동작을 유지해 로딩 완료 후 큰 delta가 전달되지 않게 한다.

## 렌더링

`Game::drawGame()`에서 플레이어와 NPC의 화면 위치는 같은 방식으로 구한다.

1. 액터의 정수 위치를 기본 tileX/tileY로 사용한다.
2. `service_.slide(actor.instance, tileX, tileY, progress)`가 true이면 보간 위치를 사용한다.
3. NPC와 플레이어 모두 instance 정수 ID로 조회한다.
4. NPC가 칸을 건너는 동안의 걷기 프레임은 진행도 `along * frames`로 고른다.
5. 주인공의 걷기 프레임은 `body.frame()`과 캐릭터 JSON의 fps로 고른다. 한 칸을 건너는 진행도에 프레임을 묶지 않는다.

주인공은 연속 보행 애니메이션을 사용한다.

- 이동이 연속되는 동안 `body.elapsed`를 매 타일마다 불필요하게 초기화하지 않는다.
- 방향이 바뀌거나 idle에서 walk로 바뀔 때만 애니메이션을 초기화한다.
- 4프레임 전체를 0.125초 안에 강제로 재생하지 않는다.
- 캐릭터 JSON의 fps를 기준으로 보행 애니메이션을 재생한다.

픽셀아트가 흔들리거나 흐려지지 않도록 최종 화면 위치는 반올림한다.

```cpp
screenX = std::round(screenX);
screenY = std::round(screenY);
```

텍스처 스무딩은 계속 비활성화한다.

## 카메라

카메라는 플레이어의 보간된 타일 좌표와 같다. 이동 중이 아니면 논리 타일 좌표를 사용한다. 그 좌표를 목표로 카메라를 한 번 더 완만하게 따라가게 두지 않는다. 지수 보간을 더하면 캐릭터가 화면 중심보다 진행 방향 쪽으로 밀린 채 남는다.

1. 보간된 플레이어 타일 좌표를 `Camera::focus()`와 같은 맵 경계 규칙으로 제한한다. 정수 타일 위에 서 있을 때의 카메라 원점은 기존 정수 포커스와 같다.
2. 그 카메라 원점을 픽셀로 한 번만 반올림한다.
3. 타일과 캐릭터는 그 같은 픽셀 오프셋으로 그린다.
4. 소수점 오프셋 때문에 화면 가장자리에 빈 칸이 생기지 않도록 타일을 상하좌우 최소 한 칸 더 그린다.
5. 타일이 화면 여백(margin)을 덮지 않도록 타일 영역만 잘라 그린다. 캐릭터 스프라이트는 기존처럼 타일 밖으로 그려질 수 있다.

## 이동 속도

현재 `src/game_config.json`의 주인공 speed는 8이다. 이는 한 타일당 0.125초이므로 보간 효과와 보행 프레임을 확인하기에 매우 빠를 수 있다.

코드에서 값을 임의로 바꾸지 말고 기존 설정을 존중한다. 다만 구현 후 다음 값을 수동으로 비교할 수 있도록 속도 계산이 정확해야 한다.

- speed 4: 한 타일당 0.25초
- speed 5: 한 타일당 0.2초
- speed 6: 한 타일당 약 0.167초
- speed 8: 한 타일당 0.125초

권장 초기 테스트 값은 4 또는 5지만 JSON 수정은 이번 코드 작업 범위에 포함하지 않는다.

## 맵 전환

1. 플레이어가 맵 경계를 넘어가는 이동을 시작할 때 기존 인접 맵 로딩 동작을 유지한다.
2. 로딩을 시작하기 전에 현재 타일 보간을 정상적으로 마무리하거나 명시적으로 취소한다.
3. 인접 맵 도착 시 이전 맵의 from/to 상태가 남지 않게 한다.
4. 새 맵의 landing cell에서 플레이어 motion 상태를 비활성 상태로 초기화한다.
5. 카메라 시각 위치도 새 맵 도착 위치로 즉시 초기화해 이전 맵 좌표와 보간하지 않는다.
6. 맵 로딩 중에는 입력 방향을 버퍼에 무한히 쌓지 않는다. 마지막 방향 하나만 유지하거나 모두 초기화한다.

## 충돌 및 예약

- 플레이어와 NPC는 목적지 타일을 이동 시작 시 예약한다.
- 보간 중인 액터의 출발 타일과 목적지 타일 처리 규칙을 일관되게 정의한다.
- 최소 구현에서는 목적지만 점유된 것으로 처리해 기존 논리 좌표 방식과 호환한다.
- 플레이어와 NPC가 같은 목적지를 동시에 선택하면 먼저 예약한 액터만 이동한다.
- 서로 위치를 교환하는 동시 이동은 허용하지 않는다.
- 막힌 타일을 향한 입력은 맵 전환 조건이 아니라면 이동을 시작하지 않는다.

## 테스트 요구사항

### 플레이어 이동

- 이동 시작 직후 논리 위치는 목적지지만 slide 진행도는 0에 가까운지 확인
- 이동 시간 절반에서 시각 위치가 두 타일의 중간인지 확인
- 이동 완료 시 시각 위치와 논리 위치가 정확히 일치하는지 확인
- speed 4에서 한 타일 이동 시간이 0.25초인지 확인
- 큰 delta가 들어와도 여러 타일을 건너뛰지 않는지 확인
- 이동 중 입력이 하나만 버퍼링되고 완료 후 적용되는지 확인
- 방향 전환과 막힌 방향 입력 시 상태와 방향 확인
- 키를 계속 누르면 타일 사이에서 불필요하게 멈추지 않는지 확인

### 애니메이션

- 이동 중 walk 상태, 이동 종료 후 idle 상태 확인
- 연속 이동 중 보행 프레임이 자연스럽게 이어지는지 확인
- 방향 변경 시 올바른 방향의 스프라이트가 사용되는지 확인
- idle과 walk 사이에서 캐릭터 크기와 앵커가 바뀌지 않는지 확인

### 카메라와 렌더링

- 플레이어 이동 중 배경이 한 타일씩 순간 이동하지 않는지 확인
- 맵 중앙과 네 가장자리에서 카메라가 맵 밖을 보여주지 않는지 확인
- 소수점 위치에서도 캐릭터와 타일이 흐려지지 않는지 확인
- 화면 가장자리에 빈 줄이 생기지 않는지 확인

### 회귀 테스트

- NPC route/radius 이동 및 slide 보간 유지
- 플레이어와 NPC 충돌 유지
- 캐릭터 배치와 맵 재진입 상태 유지
- 인접 맵 비동기 로딩과 landing cell 유지
- 기존 self-test와 새 테스트 모두 통과

## 완료 조건

- 빌드와 전체 테스트가 성공한다.
- 주인공이 타일 사이를 시각적으로 연속 이동한다.
- 키를 누르고 있는 동안 타일 경계에서 불필요하게 멈추지 않는다.
- 카메라와 배경도 주인공 이동에 맞춰 부드럽게 움직인다.
- 픽셀아트가 흐려지거나 흔들리지 않는다.
- Game에는 입력 수집과 delta 전달만 두고 이동 규칙과 충돌 판단은 CharacterService가 담당한다.
- NPC 자동 이동과 보간 동작이 깨지지 않는다.
- 리소스 이미지 및 JSON은 변경하지 않는다.
